# CCR 配置面板使用指南

本指南面向最终用户，说明如何启动、访问并使用 **ccr-ui** 可视化配置前端。
底层 API 细节见同目录的 [CCR-API操作手册.md](CCR-API操作手册.md)。

---

## 1. 这是什么

ccr-ui 是 Claude Code Router（CCR v3）的轻量可视化配置面板，用于替代无法正常访问的 CCR 自带 Web UI。
核心能力：

- **模型选择**：下拉选择模型并一键切换（自动把默认 Provider 切到该模型所属的 Provider）
- **Provider 管理**：查看 / 新增 / 编辑 / 删除 / 设为默认
- 全程走 CCR 官方 RPC（`getConfig` / `saveConfig`），不直接改配置文件

## 2. 前提条件

- CCR v3 服务正在运行（三个端口：`3456` 代理、`3457` 网关、`3458` 管理 RPC）
- 本机可读取 `~/.claude-code-router/service.json`（含访问口令）
- Python 3.11 + `uv`（本工程唯一工具链）

## 3. 启动服务

```bash
cd ccr-ui
uv sync                 # 首次需要（仅装 pytest）
uv run python main.py   # 默认监听 127.0.0.1:24678
```

启动日志（`logs/ccr-ui.log`）会打印访问地址与带口令的完整链接。

### 命令行参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--host` | 监听地址 | `127.0.0.1` |
| `--port` | 监听端口 | `24678` |
| `--no-auth` | 关闭访问口令校验（仅限本机信任环境） | 关 |
| `--token` | 手动指定访问口令 | 自动读取 `service.json` |
| `--ccr-base` | CCR RPC 地址 | `http://127.0.0.1:3458/api/ccr/rpc` |

### 环境变量 / `.env` 配置

所有命令行参数都有对应的环境变量，可写入 `.env`（复制 `.env.example` 后修改，已被 git 忽略）。
优先级：**命令行参数 > 环境变量 / `.env` > 默认值**。

| 环境变量 | 对应参数 | 默认 |
|---|---|---|
| `CCR_UI_HOST` | `--host` | `127.0.0.1` |
| `CCR_UI_PORT` | `--port` | `24678` |
| `CCR_RPC_URL` | `--ccr-base` | `http://127.0.0.1:3458/api/ccr/rpc` |
| `CCR_SERVICE_FILE` | — | `~/.claude-code-router/service.json` |
| `CCR_UI_TOKEN` | `--token` | 自动读取 `service.json` |
| `CODE_SERVER_BASE_URL` | — | 无（不打印代理链接） |

`CODE_SERVER_BASE_URL` 用于打印 code-server 访问链接，仅在通过 code-server 反向代理访问时填写，
例如 `https://code.example.com`。留空则只打印本机地址。

## 4. 获取访问口令（`t`）

访问口令就是 CCR 的 web token，三种获取方式任选：

**方式一：看启动日志**（最方便）

```bash
grep "带口令访问" logs/ccr-ui.log
# 输出形如: 带口令访问: https://code.example.com/proxy/24678/?t=xxxxxxxx
# 直接复制整条链接，或复制 ?t= 后面的 xxxxxxxx 作为口令
```

**方式二：从 service.json 读取**

```bash
python3 -c "import json,os;print(json.load(open(os.path.expanduser('~/.claude-code-router/service.json')))['url'].split('ccr_web_token=')[1])"
```

**方式三：手动打开文件查看**

`~/.claude-code-router/service.json` 里的 `"url"` 字段，格式为：
`http://127.0.0.1:3458/?ccr_web_token=<你的口令>`

## 5. 访问方式

> 下文示例中的 `code.example.com` 为占位域名，请替换为你的 code-server 基址
> （或直接通过 `.env` 的 `CODE_SERVER_BASE_URL` 配置，让启动日志打印正确链接）。

### 方式 A：code-server 内（推荐）

```
https://code.example.com/proxy/24678/?t=<口令>
```

把 `<口令>` 换成第 4 节的 token。**带 `?t=` 打开最省事**，无需再输口令。

### 方式 B：code-server 内不带口令

直接打开 `https://code.example.com/proxy/24678/`，页面会显示**访问口令**输入卡片，
把口令粘贴进去点「进入」即可（口令会保存在当前标签页的 sessionStorage）。

### 方式 C：本机直接访问

```
http://127.0.0.1:24678/?t=<口令>
```

## 6. UI 操作指南

页面自上而下三个功能区：

### 6.1 模型选择

- 顶部显示当前**默认 Provider**
- 下拉框按 Provider 分组列出所有模型（当前正在使用的模型默认选中）
- 选中新模型 → 点「切换模型」→ 保存成功后会提示（gateway 重载数秒属正常）
- **切换模型会自动把默认 Provider 切到该模型所属的 Provider**

### 6.2 Provider 管理

表格每行对应一个 Provider，右侧三个操作：

| 操作 | 说明 |
|---|---|
| **设为默认** | 把该 Provider 设为默认（`preferredProvider`），不改变当前模型 |
| **编辑** | 弹窗修改 name / type / baseurl / models / apikey（apikey 留空则不修改） |
| **删除** | 需确认；删除后其模型不可用。若删的是默认 Provider，会自动改选剩余第一个；若当前模型属于被删 Provider，会自动切到新默认 Provider 的第一个模型 |

表格里 API Key 只显示脱敏片段（如 `sk-f46****30a3`），完整 Key 不可见。

### 6.3 新增 Provider

表单字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | ✅ | Provider 唯一名（小写字母数字，如 `kimi`） |
| 类型 | 否 | `anthropic_messages` / `openai_chat_completions`；留空按 Base URL 自动推断 |
| Base URL | ✅ | Anthropic 协议以 `/anthropic` 结尾；OpenAI 协议以 `/v1` 结尾 |
| 模型 | 否 | 逗号分隔的模型 ID，如 `kimi-k2-instruct, kimi-k2-0711` |
| API Key | ✅ | 上游 API 密钥 |

填好后点「添加 Provider」，保存成功即出现在列表中。

> 新增 / 删除 / 编辑 Provider 都会触发 CCR gateway 自动重载（数秒），期间请求可能短暂失败，属正常现象。

## 7. 注意事项

1. **改模型对新会话生效**：已运行中的 Claude Code 会话不会变，需退出重开才用新模型。
2. **写操作会重载 gateway**：改动 Provider 列表后 gateway 自动重载数秒；只改模型不重载。
3. **口令安全**：口令等同于 CCR 的管理权限。带 `?t=` 的链接请勿转发给他人；
   前端打开后会自动把口令从地址栏清除并存入 sessionStorage（关闭标签页即失效）。
4. **停止 / 重启服务**：

   ```bash
   pkill -f "python main.py"     # 停止
   uv run python main.py         # 重启（启动参数同上）
   ```

5. **改动前建议备份**（CCR 官方建议）：

   ```bash
   cp ~/.claude-code-router/config.sqlite ~/.claude-code-router/config.sqlite.bak
   ```

## 8. 常见问题（FAQ）

**Q1：打开页面提示「未授权」或显示登录卡片？**
没有提供有效口令。用带 `?t=` 的链接，或在卡片里输入口令（见第 4、5 节）。

**Q2：打开页面提示「连接失败」？**
说明前端脚本已加载但拿不到数据。请确认：
- `uv run python main.py` 正在运行（`pgrep -f "python main.py"`）；
- 服务日志无报错（`tail -20 logs/ccr-ui.log`）；
- 若日志为空，先 `pkill -f "python main.py"` 再重新启动。

**Q3：切换模型后没生效？**
新模型只在**新开的** Claude Code 会话中生效；如果列表里没有想要的模型，先检查对应 Provider 是否已配置该模型。

**Q4：删除 Provider 后 gateway 一直报错？**
删除操作会触发 gateway 重载，等几秒即可自动恢复。若持续异常，用第 7 节的备份恢复 `config.sqlite`，再重启 CCR。

**Q5：想完全不要口令？**
仅在完全信任的本地环境运行 `uv run python main.py --no-auth`。不建议在可被外部访问的环境关闭口令。
